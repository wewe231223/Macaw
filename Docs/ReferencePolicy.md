# 참조와 소유권 정책

이 문서는 직접 관리하는 `Source`, `Games`, `Templates`, `Tests` 코드에 적용한다. 생성 결과물과 외부 라이브러리는 생성기 또는 해당 API의 계약을 따른다. 현재 빌드와 생성기 입력에 포함되지 않는 `Regacy`의 이전 구현 보관본은 수정 대상에서 제외한다. 참조 표현은 대상의 이름이나 접두사가 아니라 소유권, 대상의 수명, 저장 필요성에 따라 선택한다.

## 선택 기준

| 상황 | 표현 | 책임 |
| --- | --- | --- |
| 값으로 포함할 수 있는 단독 상태 | 값 멤버 | 포함한 객체가 수명을 관리한다. |
| 동적으로 생성한 객체의 단독 소유권 | `std::unique_ptr<T>` | 생성 결과와 소유권 이전도 `unique_ptr`로 표현한다. |
| 둘 이상의 소유자가 실제로 수명을 유지해야 하는 스냅샷·공유 리소스 | `std::shared_ptr<T>` | 단순 조회나 삭제 감지 목적으로 도입하지 않는다. |
| 호출 중 빌리는 객체, 선택적인 인수, 조회 결과 | `T*`, `const T*` | 반환은 소유권을 이전하지 않는다. 주소를 보관하려면 수명을 다시 판단한다. |
| 호출 중 반드시 존재해야 하는 객체 | `T&`, `const T&` | 참조도 대상의 수명을 연장하지 않는다. |
| 대상이 참조자보다 오래 존재하는 것이 소유 구조나 연결 해제로 보장되는 멤버 | 로우 포인터 또는 C++ 참조 | 소유자의 종료 순서, 교체 시 초기화, 등록 해제 중 하나로 보장한다. |
| 멤버·컨테이너·지연 작업에 보관하는 비소유 UObject 참조 | `TObjectRef<T>` | 대상 타입과 세대를 함께 검증한다. 수명을 연장하지 않는다. |
| 여러 UObject 타입을 함께 다루는 선택·범용 편집 참조 | `TObjectRef<UObject>` | 공통 기반 타입이 알려져 있으므로 타입이 붙은 참조를 유지한다. |
| 레지스트리·순회·델리게이트 구현·네이티브/관리 코드 ABI의 객체 식별 | `FObjectHandle` | 내부 표현으로만 사용한다. `FromHandle()`과 `GetHandle()`로 경계에서 명시적으로 변환한다. |
| 엔진이 소유한 월드 컨텍스트의 선택·라우팅 | `FWorldHandle` | 해당 엔진의 `GetWorld()`로 해석한다. 전역 객체 핸들과 구분한다. |
| 장면 저장·로드 및 복제의 중간 참조 값 | `FObjectReference` | GUID 저장·복원과 `Bind()`를 담당한다. 일반 객체 필드는 `TObjectRef<T>`로 선언하고 리플렉션이 중간 값으로 변환한다. |
| 파일에 저장할 에셋 의존성 | Content 상대 경로 또는 에셋 식별자 | 에셋 매니저를 통해 해석한다. 메모리 주소와 런타임 핸들을 파일에 저장하지 않는다. |
| 변경 가능한 컨테이너 원소를 장기간 식별 | 소유자 참조 + 안정적인 ID | 접근 시 원소를 다시 조회한다. 필요하면 개정도 확인한다. |
| GPU·윈도우·FBX·Assimp·UI 등 외부 자원 | `ComPtr`, 해당 API의 핸들·파괴 함수 | 외부 API가 정한 소유권 이전과 해제 방법을 따른다. |

`UObject` 상속 여부는 리플렉션, 직렬화, 엔진 객체 식별 기능의 필요성으로 결정한다. 참조 타입을 맞추기 위해 서비스와 인터페이스를 `UObject`로 바꾸지 않는다. 이 엔진의 `UObject`에는 GC에 의한 자동 수명 관리가 없으므로 `unique_ptr`와 필요한 공유 소유를 유지한다.

## 로우 포인터를 유지하는 경우

- `GetOwner()`, `GetWorld()`, `GetRootComponent()`, `FindActor()`, `LoadMesh()` 같은 조회 함수는 비소유 포인터를 반환할 수 있다. 반환값을 멤버·지연 작업·다음 프레임에 보관하는 쪽이 별도로 수명을 보장해야 한다.
- `UWorld → ULevel → AActor → UActorComponent → UAnimInstance`의 소유 관계에서 부모를 가리키는 역참조는 소유자가 먼저 연결을 끊고 자식을 정리하는 계약 아래 로우 포인터를 사용할 수 있다. `UObject::Outer`는 이름 범위이며 소유권 자체를 뜻하지 않으므로 세대 핸들을 사용한다.
- 액터의 루트 컴포넌트, 카메라 관리자의 기본 셰이크 모디파이어처럼 자신의 소유 목록에 있는 객체를 가리키는 포인터는 목록에서 제거할 때 함께 비운다.
- `FAssetManager*`, `IRendererModule*`, `FSceneInterface*`, 에디터 컨텍스트·뷰포트 서비스 등은 이용자를 먼저 종료하는 계약으로 빌린다. 프로젝트나 렌더러가 교체될 때 이용자도 종료하거나 다시 연결해야 한다.
- 에셋 매니저는 경로 캐시에서 은퇴시킨 객체를 `mRetired`로 옮겨 매니저가 소멸할 때까지 유지한다. 컴포넌트·렌더 프록시·에디터·뷰어에 저장하는 에셋 참조도 `TObjectRef<T>`를 사용한다. 소유권과 에셋 경로 저장 방식은 유지한다.
- `SetPreviewAssets()`, 애니메이션 노드의 직접 에셋 지정, 뷰어의 외부 에셋 지정도 저장하는 쪽에서는 `TObjectRef<T>`를 사용한다. 호출자가 먼저 파괴하면 조회 결과가 null이 되며, 이용자는 필요한 시점에 유효성을 확인한다.
- 렌더 명령·뷰 정보·포즈 평가 컨텍스트·리플렉션 편집 이벤트의 포인터는 해당 호출이나 프레임의 작업 범위에서 빌린다. 그 범위가 끝난 뒤 주소를 유지하지 않는다.
- 리플렉션 타입과 프로퍼티 메타데이터는 레지스트리가 수명을 유지한다. 별도의 객체 참조로 바꾸지 않는다.

## 런타임 참조의 유효성

`TObjectRef<T>::Get()`과 `IsValid()`는 레지스트리의 슬롯·세대와 실제 객체 타입을 함께 검사한다. 파괴되었거나 타입이 다르면 null/false를 반환한다. `operator->`와 포인터 변환도 같은 조회를 수행한다. 파생 타입에서 기반 타입으로, 가변 타입에서 const 타입으로의 변환만 암시적으로 허용한다. 역방향 변환에는 명시적인 타입 검사가 필요하다.

내부 타입인 `FObjectHandle::IsValid()`는 슬롯·세대 값의 형식만 검사한다. 형식이 맞아도 객체가 파괴되었을 수 있다. 슬롯을 재사용해도 이전 세대의 참조가 새 객체를 가리켜서는 안 된다. `TObjectRef` 사이의 동등성과 해시는 살아 있는지와 독립적으로 대상의 식별을 유지한다.

객체가 할당되어 있다는 사실과 현재 작업에 사용할 수 있다는 사실은 구분한다. 액터가 삭제 대기 상태이거나, 컴포넌트가 예상한 월드에 속하지 않으면 게임플레이 작업에서 제외한다. 월드 범위 참조는 `ContainsObject()` 등의 소속 검사도 거친다.

해석한 포인터는 작업 범위에서만 사용한다. 대상 삭제·월드 교체·컨테이너 재할당이 가능한 콜백을 호출한 뒤 다시 사용할 때는 소유 구조 또는 실행 전달 범위가 수명을 보장하는지 확인하고, 보장하지 못하면 다시 해석한다. 핸들은 스레드 동기화나 수명 고정을 제공하지 않는다. 객체 레지스트리의 생성·파괴·해석은 소유 스레드에서 수행한다.

객체를 식별하는 캐시 키에는 주소만 쓰지 않는다. 수명 독립성이 있는 `UObject` 캐시는 `TObjectRef<T>`와 `TObjectRefHash<T>`로 슬롯과 세대를 모두 비교한다. 원소의 주소를 키로 써도 되는 경우는 컨테이너나 공유 스냅샷이 모든 키 대상의 수명을 유지하고 주소 변경 전에 캐시를 비우는 경우다.

## 저장과 재연결

`FObjectReference`는 기존의 GUID·핸들을 가진 값 타입으로 유지한다. GUID 생성자, 객체 생성자, `GetGuid()`, `Resolve()`, `Bind()`를 제공하며 리플렉션·직렬화의 중간 값으로 사용한다. `TObjectRef<T>`에서 이 값으로 변환한 뒤 저장하고, 로드·재연결 후 `ToObjectRef<T>()`로 타입을 검증하여 복원한다. 일반 게임플레이·에디터 상태에 이 타입을 직접 보관하지 않는다.

`TObjectRef<T>`도 미연결·파괴된 대상을 다시 저장할 때 GUID를 잃지 않도록 내부에 GUID를 보관한다. 현재 크기는 24바이트이며 단순 핸들의 8바이트보다 크다. 핸들과 GUID는 메모리에만 유지하고 파일에는 GUID 또는 에셋 경로를 저장한다. 두 참조 타입 모두 소유권, GC, 자동 로드를 제공하지 않는다.

장면 로드에서는 모든 객체를 만든 다음 GUID 대응표로 참조를 연결한다. 장면 복제에서는 GUID 재매핑 후 복제된 객체에 연결한다. 대응표에 없는 대상은 참조의 GUID를 유지하되 해석 결과를 null로 처리한다. 외부 프로젝트 서비스나 렌더 인터페이스는 장면 객체처럼 저장하지 않고 실행 환경에서 연결한다.

에셋 참조는 경로를 저장하고 캐시 포인터를 재구성한다. 매니저 수명 동안 주소를 유지한다는 계약과, 같은 경로에서 최신 에셋을 다시 조회한다는 동작은 서로 다른 계약이다. 은퇴한 포인터는 안전하게 남지만 자동으로 새 에셋을 가리키지는 않는다.

## 이벤트와 등록

- `UObject` 멤버 함수 구독에는 `TDelegate::AddDynamic()`을 사용한다. 호출 직전에 대상의 세대 핸들을 확인한다.
- `AddRaw()`와 객체를 캡처하는 일반 람다는 대상이 구독보다 오래 살아 있거나 파괴 전에 구독을 해제하는 경우에 사용한다.
- 외부 수신자를 보관하는 서비스는 등록 해제 경로를 제공해야 한다. 로딩 상태 수신자는 자신의 소멸 시 현재 등록을 해제하며, 교체된 다른 수신자의 등록을 지우지 않는다.
- C#에는 엔진 객체 주소를 넘기지 않고 슬롯·세대 핸들을 넘긴다. 관리 코드의 객체 래퍼는 네이티브 객체의 소유자가 아니다. ABI의 텍스트·임시 배열 포인터는 정해진 호출 범위에서만 사용한다.

## 모듈별 점검 결과와 적용 근거

직접 작성한 네이티브 코드와 관리 코드, 프로젝트 템플릿을 대상으로 포인터 멤버·컨테이너, 소유권 이전, 파괴·교체 경로, 지연 등록을 점검했다. 외부 라이브러리와 생성 결과물을 직접 일괄 변경하지 않는다.

| CoreUObject | 레지스트리의 주소 저장, 메타데이터 포인터, 호출 범위 복제 대응표, 세대 핸들 기반 순회와 델리게이트 | 타입·세대 검증을 수행하는 `TObjectRef<T>`와 해시, 기존 `FObjectReference`와의 직렬화 변환 |
| Serialization | JSON 문서 내부 포인터와 메모리 아카이브 버퍼는 소유 문서·버퍼의 수명 안에서 사용 | 소유 구조 유지 |

시퀀스 바인딩과 애니메이션 그래프 원본 노드는 변경 가능한 배열에 들어 있으므로 장기 보관 주소를 제거했다. 바인딩은 GUID, 그래프 원본은 그래프 핸들·노드 ID·개정으로 다시 조회한다. 런타임 포즈 노드 사이의 포인터는 같은 애니메이션 인스턴스가 소유하고 함께 재구성하므로 유지한다.

충돌 결과의 대상 지정은 `SetActor()`와 `SetComponent()`, 조회는 `GetActor()`와 `GetComponent()`를 사용한다. 결과를 복사하거나 다음 프레임까지 보관해도 삭제된 대상의 주소를 노출하지 않는다.
